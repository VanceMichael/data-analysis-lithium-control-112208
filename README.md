# 提锂吸附柱换料的寿命分析与轮换决策

运行日自换料试运行起计；载荷采用归一处理量，采样缺失用问号。所有资料均为合成记录。
文件编码为 UTF-8，数字、日期及标记在原始记录中均以字符串保存。问号表示来源未能提供
该值；加号分隔来源系统使用的组合编号。

本应用在交班后对同一组来源表**整体、确定性地重算**，输出带依据、估计区间与阻塞原因的
结构化结果，供计划员签下一个运行周期。纯 Node.js 22 实现，无第三方依赖。

## 资料

ratio 是相对于额定处理效果的比率。线路 units 中的柱串联且需同时可用，不同线路并联。
备用柱同窗只替代一个已停用单元，不能增加原线路上限。建议中的风险上限按相应交货窗给出。

- `performance.json` 记录字段为 `column`、`load_lot`、`day`、`feed`、`processed`、`ratio`、`state`。
- `lab.json` 记录字段为 `column`、`day`、`revision`、`ratio`、`state`。
- `paths.json` 记录字段为 `line`、`units`、`capacity`、`backup`。
- `work.json` 记录字段为 `task`、`column`、`period`、`status`、`authority`。
- `delivery.json` 记录字段为 `window`、`min_qty`、`max_combined_risk`。
- `thresholds.json` 记录字段为 `feed`、`min_ratio`、`window_ready`。
- `maintenance.json` 记录字段为 `window`、`crew_slots`、`restart`。
- `product_rules.json` 记录字段为 `customer`、`grade`、`hold_allowed`、`latest`、`minimum`。
- `handoffs.json` 记录字段为 `piece`、`line`、`qty`、`col`、`window`、`condition`、`customer`。
- `storage.json` 记录字段为 `window`、`hold_volume`、`lab_slots`。

## 领域规则与实现位置

### 1. 按料次的实际运行经历（`src/experience.js`）

- 以 `柱+装填批次(load_lot)` 为一个料次，逐日区分 **运行 / 旁路 / 停机（含缺测）/ 拆装**。
- 磨损暴露只累计"运行"日的归一处理量；旁路读数保留但不参与寿命比较、不计磨损。
- 进料入口条件变化（如换低浓度卤水后读数好转）显式生成进料分段，跨进料读数不混合比较。
- 每个运行日归为一种寿命证据：**性能越界 / 正常读数 / 证据待查 / 取样不足 / 计划更换 / 非运行经历**。
- **有效化验是权威读数**：同柱同日有效化验覆盖运行读数，并可补救缺测日；化验未生效
  （如"报告待复核"）时证据挂起，原始读数保留可追溯但不得直接判越界。
- 计划拆除与期末仍在役都是**右删失**，不伪造自然失效时间。

### 2. 取样纪律（`src/sampling.js`）

- 同柱同日只对应一份独立样本；多次化验按 `revision` 归并取最新，跨班复用的同一份样本
  不会被当成独立样本。
- `storage.lab_slots` 是**固定采样上限（化验名额）**，报告中显式注明它不是设备寿命依据。
- 待检/重检产物与待查寿命证据各占一个名额，同一样本被多个方案引用只占一次。

### 3. 寿命估计与区间（`src/life.js`、`src/risk.js`）

- 采用 **Kaplan–Meier 乘积极限**：删失不进失效计数，待查单位不进风险集；
  Greenwood 方差 + log(-log) 变换给出生存函数 95% 区间与中位寿命区间。
- 样本内无失效、无观察或区间无法闭合时，显式返回"无有效参考"及原因，绝不编造数值。
- 同时计算朴素的"故障平均寿命"仅作对照，并固定附带偏差警告：它忽略删失与待查，
  会把同批老化柱一起压到高负荷时段，**禁止用于排程**。
- **失效依赖**：同料次+共用进料、以及仅共用进料的柱分别归入依赖簇，簇内声明不独立。
  串联线路联合风险取保守上界（完全正相关 max），并联给 Fréchet 边界；
  交付窗 `max_combined_risk` 用区间上界判定。

### 4. 换柱排程（`src/schedule.js`）

- 已开工换料的柱在该窗口计入不可用；已签未开工任务在未获授权移位确认前锁柱，
  并给出移位确认条件（`不可移位/班长/计划员`）；候选任务未签不锁柱。
- 串联单元必须同时可用；单单元停用可由备用柱替代但不增加线路上限；
  串联两个单元同时停用则单根备用无法挽救。
- **共用备用柱同窗只替代一个单元**：两条线路不能各自把同一备用柱算成已保障，冲突显式报出。
- 值班员可并列比较三类方案：**换一根 / 降负荷 / 改用备用线路**，各自给可行性、
  能力、是否满足排定负荷与阻塞原因；施工名额（`crew_slots`）满时换料方案判不可行。
- 新化验使证据待查时，相关柱与所在线路的替代方案重判可用性，并在 `committedImpact`
  中显示对已承诺生产量的缺口影响。

### 5. 客户验收与待检量（`src/product.js`）

- 稳定品级要求来源柱取得首批稳定读数（`window_ready`）；新装填柱未稳定前只能产出待检量。
- 待检量物理占用 `hold_volume` 容器与 `lab_slots` 名额：不能一边留给允许待检的客户，
  一边又按连续可用量出给只收稳定量的客户。
- 化验改判支持 **转可交 / 降级 / 否决**；**已发货批次不收回**，只保留原签发依据并登记
  应补沟通。
- 按客户 `latest` 等待时限与 `minimum` 最低量输出阻塞链：可交量、还在等哪件结果、
  紧缺时哪家承诺会被卡住。

### 6. 运行日查询与下一轮入口（`src/query.js`、`src/ingest.js`）

- 按运行日查询返回候选任务、已签窗口、实测依据，并把问题显式分成三类：
  **风险确实上升 / 缺乏证据 / 根本安排不下**。
- 运行日→窗口采用显式可复核的锚定约定（计划拆除日及其之前属当前施工窗，之后按相同
  运行日跨度滚动到下一窗口），约定原文随查询结果一并返回。
- 新交班记录与维修回执经 `ingest` 统一入口追加：全字符串原始值、引用闭合校验、
  业务键幂等、快照隔离不污染上一轮输入；维修回执自动推进任务完工并补复启/装填记录。

## 代码结构

```
src/
  constants.js   状态词表与证据/风险枚举
  parse.js       字符串原始值解析、字段与跨表引用核对
  sampling.js    化验样本台账、修订归并、化验名额
  experience.js  料次运行经历、进料分段、日证据分类
  life.js        Kaplan–Meier、区间、无参考条件、依赖簇、剩余寿命
  risk.js        单柱/串联/并联组合风险与交付窗上限判定
  schedule.js    任务权限、窗口可用性、备用冲突、三类方案、承诺影响
  product.js     稳定读数、待检占用、交付评估、化验改判、客户阻塞
  query.js       运行日-窗口映射、按日三分类查询
  ingest.js      交班录入与维修回执（幂等、引用校验、快照隔离）
  app.js         主引擎：一次可重算的完整分析
  io.js / cli.js 数据加载与命令行
test/            node:test 规则级测试（含原 data.test.js）
```

## 运行

使用 Node.js 22。项目无需下载第三方依赖。

```sh
npm ci --offline --ignore-scripts
npm test                 # 全部规则测试
npm run data:check       # 仅核对合成资料可读性与引用闭合
```

命令行（均输出确定性 JSON）：

```sh
node src/cli.js analyze                       # 完整重算
node src/cli.js life [--feed A]               # 料次寿命证据与估计区间
node src/cli.js schedule [--window W1]        # 窗口排程、三类方案、风险上限
node src/cli.js delivery [--window W1]        # 待检占用、交付可行性、客户阻塞
node src/cli.js day 4                         # 按运行日查询（三类风险）
node src/cli.js ingest handoff.json           # 交班资料走统一运行入口
node src/cli.js receipt M1 5 L4               # 维修回执：完工并补复启记录
node src/cli.js verdict P4 转可交 --basis "..."  # 化验改判与交付重估
```
